## P1 — Ports: the enabling refactor

**Goal:** four seams that let the same code run as 23 containers or as one.
**Hard rule for this whole phase: zero behaviour change.** Cluster path stays the
default implementation of every port; the existing test suite is the proof.

### P1.1 — `shared/bus` port + Kafka adapter · M
- **New:** `shared/bus/bus.go`
  ```go
  type Bus interface {
      Publish(ctx context.Context, topic, key string, value []byte) error
      PublishBatch(ctx context.Context, topic string, entries []*models.LogEntry) error
      Subscribe(ctx context.Context, group string, topics []string, h Handler) error
      Close() error
  }
  type Handler func(ctx context.Context, topic string, key, value []byte) error
  ```
- **New:** `shared/bus/kafka_adapter.go` — wraps the existing
  [`shared/kafka`](../../shared/kafka/) `Producer` + `ConsumerGroup` verbatim; the
  `MessageHandler(*sarama.ConsumerMessage)` signature is adapted here so sarama
  stops leaking into callers.
- **Modify (mechanical, one commit each is fine if it gets large):** every
  `kafka.NewProducer()` / `kafka.NewConsumerGroup()` call site in
  `log-service/cmd`, `alert-service/cmd`, `correlation-service/cmd`,
  `topology-service/cmd`, `gateway-service/internal/logbridge`,
  `gateway-service/internal/ingestproxy` → take a `bus.Bus`.
- **Pure logic to unit-test:** `bus.TopicFor(kind)` and the sarama↔Handler
  adaptation (message → (topic,key,value), error propagation, no silent drops).
- **Tests:** existing Kafka integration tests must pass untouched — that is the
  no-behaviour-change proof.
- **Commit:** `refactor(shared): introduce the bus port; Kafka becomes an adapter`

### P1.2 — In-process bus adapter · M
- **New:** `shared/bus/inproc_adapter.go` — bounded per-topic ring buffer with
  **disk spill** (`$DATA_DIR/bus/<topic>/*.seg`, 64 MB segments, fsync on rotate)
  so a lite deployment does not lose the queue on restart. At-least-once, with an
  offset file per consumer group. Backpressure = block the producer once the ring
  and the spill budget are full — **never drop silently**.
- **Pure logic to unit-test:** segment rotation, offset commit/replay, at-least-once
  redelivery after a simulated crash, backpressure at the boundary, concurrent
  producer/consumer ordering per topic.
- **Tests:** a conformance suite `shared/bus/conformance_test.go` run against
  **both** adapters — same assertions, both implementations. This is what keeps
  lite and cluster semantically identical.
- **Commit:** `feat(bus): in-process adapter with disk spill + shared conformance suite`

### P1.3 — `shared/db` dialect shim · M
- **Modify:** [`shared/db/postgres.go`](../../shared/db/postgres.go) → add
  `shared/db/db.go` with `Open(ctx) (*sql.DB, Dialect, error)` where
  `Dialect ∈ {postgres, sqlite}`, selected by `DATABASE_URL` scheme.
- **New:** `shared/db/dialect.go` — the small translation surface actually used by
  our migrations and queries: `JSONB`→`TEXT`, `SERIAL`/`BIGSERIAL`→`INTEGER PRIMARY KEY
  AUTOINCREMENT`, `NOW()`→`CURRENT_TIMESTAMP`, `$1`→`?` placeholder rewriting,
  `ON CONFLICT` differences, and `pg_advisory_xact_lock` → a SQLite `BEGIN IMMEDIATE`
  equivalent (**required** — the F20 audit hash-chain depends on that lock; get
  this wrong and the chain forks).
- **Modify:** `shared/migrate` — apply the dialect rewrite to embedded migration SQL.
- **Pure logic to unit-test:** every rewrite rule, table-driven; a golden test that
  runs **all 34 existing migrations** against SQLite and asserts the resulting
  schema matches the Postgres one (column names + types + constraints).
- **Risk note:** if a migration proves untranslatable, add a
  `NNN_name.sqlite.sql` sibling rather than degrading the Postgres one.
- **Commit:** `refactor(db): dialect shim so migrations run on Postgres or SQLite`

### P1.4 — `GraphStore` port in topology-service · S
- **New:** `topology-service/internal/repository/graphstore.go` — the interface
  extracted from [`neo4j_repo.go`](../../topology-service/internal/repository/neo4j_repo.go)
  (upsert service, upsert edge, graph read, upstream/downstream walk, catalog
  CRUD, tenant delete). Neo4j usage is shallow and confined to 4 files, so this
  is genuinely small.
- **New:** `topology-service/internal/repository/sql_graph_repo.go` — adjacency
  tables (`graph_nodes`, `graph_edges`) over `shared/db`; the upstream/downstream
  walks become recursive CTEs (bounded depth, matching today's Cypher depth cap).
- **Modify:** `gateway-service/internal/tenantdata/purge.go` — purge through the
  port, not Neo4j directly, so tenant deletion keeps working in lite.
- **Pure logic to unit-test:** the recursive-CTE walk vs the Cypher walk on the
  same fixture graph — identical node sets, identical cycle handling.
- **Tests:** run `topology-service/internal/handler/api_test.go` against both impls.
- **Commit:** `refactor(topology): GraphStore port + SQL adjacency adapter`

### P1.5 — `shared/blob` port · S
- **New:** `shared/blob/blob.go` — `Put/Get/List/Delete/Stat` over S3, Azure Blob,
  GCS, and local filesystem; endpoint/credential resolution moves out of the
  per-service env reads.
- **Modify:** ClickHouse `storage.xml` stays as-is (CH manages its own disks);
  this port is for **our** artifacts — bus spill, compactor output (P3.2), report
  PDFs (P5.5), enrichment tables (P6.5).
- **Tests:** conformance suite against local fs + MinIO (already in compose).
- **Commit:** `feat(shared): blob port for object storage across providers`

## P2 — `pulsetrace-lite`

**Goal:** `docker run -p 8080:8080 pulsetrace/pulsetrace` → working product in
under 60 seconds with nothing else installed.

### P2.1 — Single binary with role flags · L
- **New:** `cmd/pulsetrace/main.go` at repo root — one binary, OpenObserve's own
  model: `--role=all|gateway|ingest|query|worker|notify`. In `all` it starts every
  service's HTTP mux on one port under path prefixes and every worker as a
  goroutine; in split roles it starts one. Requires each service to expose
  `RegisterRoutes(mux)` + `StartWorkers(ctx, deps)` — most already do
  (`correlation-service`, `topology-service` handlers already take a mux).
- **New:** `shared/runtime/mode.go` — `Mode` resolved **once** at startup from
  `PULSETRACE_MODE=lite|cluster`, wiring the port implementations:
  lite ⇒ `bus.InProc` + `db.SQLite` + `repository.SQLGraph` + `blob.LocalFS`;
  cluster ⇒ today's implementations. A mode mismatch (e.g. lite + `KAFKA_BROKERS`
  set) is a **startup error**, not a silent preference.
- **Modify:** `go.work` — add the root module.
- **Pure logic to unit-test:** `ResolveMode(env)` — every valid combination, and
  every contradictory one rejected with a specific message.
- **Commit:** `feat(runtime): single binary with role flags + lite/cluster wiring`

### P2.2 — Embedded telemetry stores · L
- **Spike first (timeboxed, 3 days, write the findings into the slice):** logs —
  embed Quickwit in library mode vs. talk to a bundled `quickwit` process in the
  same container. Analytics — `chdb` (embedded ClickHouse, keeps our SQL dialect)
  vs DuckDB (better Go story, dialect drift). **Recommendation to validate:
  bundled Quickwit process + chdb**, because it keeps both the index format and
  the SQL dialect identical to cluster mode, which is what makes P2.4 possible.
- **New:** `shared/analytics/` — the seam the handlers query through, so
  `queryScoped` targets either the ClickHouse HTTP endpoint or chdb.
  **Critical:** the `assertTenantScoped` / `referencesTenantScopedTable` guard in
  [`clickhouse.go`](../../gateway-service/internal/handler/clickhouse.go) must run
  on **both** paths, and `TestNoRawTenantTableReads` must ratchet both.
- **Tests:** the full gateway handler suite against the embedded engine.
- **Commit:** `feat(lite): embedded analytics + search engines behind the analytics seam`

### P2.3 — Image, first-run, and the 60-second proof · M
- **New:** `Dockerfile.lite` — multi-stage; final image = the one binary + the
  bundled Quickwit + the built frontend, `$DATA_DIR` as the only volume.
- **New:** first-run bootstrap — auto-create the `default` tenant, an admin user
  with a generated password printed **once** to stdout, seed the Quickwit index,
  run migrations. No manual step between `docker run` and the login screen.
- **Modify:** `frontend/src/components/Settings/` — a mode badge; anything
  cluster-only renders an explicit "requires cluster mode" state (never a dead
  button, never fake success — house rule).
- **Tests:** `frontend/tests/e2e/lite.spec.ts` — boot from a clean volume, log in,
  POST an OTLP log, assert it appears in Explorer, **assert wall-clock < 60 s**.
- **Commit:** `feat(lite): single-container image + first-run bootstrap`

### P2.4 — lite → cluster upgrade path · M
- **New:** `scripts/lite-to-cluster.sh` — SQLite → Postgres dump/restore through
  the dialect shim; bus spill drained into Kafka; Quickwit index directory copied
  (identical format, which is why P2.2 chose the bundled process).
- **Tests:** an integration test that ingests in lite, upgrades, and asserts the
  same query returns the same rows in cluster mode.
- **Commit:** `feat(lite): data-compatible upgrade to cluster mode`

## P3 — Storage economics

### P3.1 — Object-store-primary tiering · M
- **Modify:** `clickhouse/storage.xml` — move the app-owned tables to a policy
  whose hot window is **hours**, not days: `TTL toDateTime(Timestamp) + INTERVAL 6 HOUR

- **Verify with P0.1:** does `otel_logs` hold a duplicate of what Quickwit already
  indexes? If yes (likely — the collector writes it and nothing queries it), stop
  writing it. That is a pure cost deletion.
- **DoD:** re-run `run-benchmark.sh`; bytes/GB drops, query p95 stays within 1.2×.

### P3.2 — Compactor worker · L

## P4 — Query engine

**This phase contains the highest-severity security surface in the codebase.**
P4.1 exists specifically so the security core lands, and is reviewed, *before*
any endpoint exposes it.

### P4.1 — Safe SQL core (no endpoint yet) · L
- **New:** `gateway-service/internal/sqlq/` —
  - `parse.go`: parse with a real SQL parser (**not** regex —
    `github.com/auxten/postgresql-parser` or `vitess sqlparser`; pick in the
    slice and record why).
  - `policy.go`: allowlist — `SELECT` only; no DDL/DML; no `system.*`; no
    `file()`/`url()`/`remote()`/`s3()` table functions; no `INTO OUTFILE`; bounded
    subquery depth; bounded JOIN count.
  - `tenant.go`: **AST-level** injection of the tenant predicate into every
    tenant-scoped table reference, including inside subqueries, CTEs, and JOINs.
    String concatenation anywhere in this file is a review failure.
  - `budget.go`: per-role max scanned rows / bytes / time-range / wall-clock.
- **Modify:** `gateway-service/internal/handler/clickhouse.go` — `queryScoped`
  gains a `FromAST` entry point so the F0.3 fail-closed guard still runs on
  generated SQL.
- **Modify:** `tenant_scoping_guard_test.go` — extend `TestNoRawTenantTableReads`
  to cover `sqlq`, so a future contributor cannot bypass it.
- **Tests (this is the slice's real deliverable):** a table-driven **escape suite** —
  comment injection, UNION to another tenant's table, CTE aliasing a scoped table,
  subquery in `WHERE`, JOIN against a system table, nested view, `FORMAT` abuse,
  stacked statements, unicode/quoting tricks. Every case asserts either rejection
  or a correctly-injected predicate. Plus a cross-tenant fixture test: tenant A's
  query provably cannot return tenant B's row.
- **Gate:** run `/security-review` on this slice before merge. If AST-level tenant
  safety cannot be demonstrated, **ship the endpoint single-tenant/on-prem only**
  and say so in the docs.
- **Commit:** `feat(sqlq): sandboxed SQL core with AST-level tenant injection`

### P4.6 — Acceleration · M
- **New:** `gateway-service/internal/querycache/` — result + histogram cache in
  the **Redis already in compose and barely used**, keyed by
  `(tenant, normalized-sql-hash, time-bucket)`; only closed time ranges are
  cached, the trailing open bucket never is.

## Risk register (per phase)

| Phase | Risk | Mitigation |
| :---: | --- | --- |
| P1 | Four ports touch every service; a subtle regression is invisible until production | Cluster path stays the default impl; the **existing** suite is the acceptance test; conformance suite runs both adapters; land one port per commit |
| P1.3 | Dialect shim breaks the F20 audit hash-chain (it depends on `pg_advisory_xact_lock`) | A dedicated SQLite-lock equivalent + a chain-fork test under concurrent writers, before any other migration is translated |
| P2.2 | Embedded-engine spike picks wrong; dialect drift makes lite and cluster answer differently | Timebox to 3 days; bias to chdb + bundled Quickwit **because** they preserve dialect and index format; a golden-query test that runs identically on both modes |
| P3.2 | Retention off-by-one deletes live data | `partitionsToDrop` is table-tested at the boundary; dry-run mode logs what it *would* drop for one full cycle before enforcement is enabled |
| P4.1 | A multi-tenant SQL endpoint is how tenant isolation dies | AST-level injection only; escape suite; ratchet extension; mandatory `/security-review`; ship single-tenant-only if it cannot be proven |
| P4.5 | `POST /api/v1/series` already exists as an ingest route | Namespace the read API under `/api/v1/prom/*` — do not overload |
| P5.4 | Silent partial dashboard conversion erodes trust | Per-panel translation report; unsupported panels render as an explicit placeholder |
| P6.3 | Pipelines sit on the ingest hot path | Perf gate with pipelines enabled must hold the existing p95/p99 thresholds; per-node error isolation with a dead-letter stream |
| P6.3 | "VRL-compatible" that silently mis-evaluates | Unsupported constructs are hard compile errors; the supported list is published in-product |
| P6.5 | Rewriting PII redaction could regress protection | New detectors must pass the old suite plus the false-positive cases; ship both paths behind a flag for one release |
| P7 | Seven decoders, seven parsing-bug surfaces | Real captured payloads in `testdata/`; fuzz the decoders |
| P8.5 | Compliance is calendar-bound and always started late | Start it on day one of P1, in parallel, tracked separately from engineering phases |
| All | This plan is roughly the size of ROAD_TO_100 again | Never start a phase before its predecessor's exit gate is green; one moat epic per phase keeps the differentiator alive |

## Recommended start

1. **P0.4** (README truth pass) — one hour, disproportionate credibility.
2. **P0.1 + P0.2** — the benchmark harness. Everything downstream is guesswork
   without a measured baseline.
3. **P1.1** — the bus port. Smallest of the four, proves the refactor pattern, and
   unblocks the P2 critical path.
4. **P4.1** — the safe SQL core, in parallel on Track B. It is the long pole for
   the entire query/dashboard half of the plan and needs review time, so it should
   start early even though it ships nothing user-visible.

Then P1.2–P1.5 and P4.2 in parallel, converging on P2 and P5.
